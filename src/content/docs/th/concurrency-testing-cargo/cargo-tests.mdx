## Cargo: ระบบ Build และ Package Manager ของ Rust

Cargo คือระบบ build อย่างเป็นทางการและ package manager ของ Rust โปรเจกต์ Rust ทุกโปรเจกต์คือ **crate** และ Cargo จัดการ dependency, build, test และเอกสารของตัวเอง

### คำสั่ง Cargo ที่จำเป็น

```bash
# Create a new binary project
cargo new my_project
cd my_project

# Create a new library crate
cargo new my_lib --lib

# Build in debug mode (fast compile, unoptimized)
cargo build

# Build in release mode (slow compile, optimized)
cargo build --release

# Build and run in one step
cargo run

# Run with arguments
cargo run -- arg1 arg2

# Check for compile errors without producing a binary
cargo check

# Add a dependency
cargo add serde --features derive

# Update dependencies to latest compatible versions
cargo update

# Format code
cargo fmt

# Run the linter
cargo clippy
```

### โครงสร้าง `Cargo.toml`

```toml
[package]
name    = "my_project"
version = "0.1.0"
edition = "2024"

[dependencies]
serde       = { version = "1", features = ["derive"] }
tokio       = { version = "1", features = ["full"] }
anyhow      = "1"

[dev-dependencies]
# only compiled for tests and benchmarks
pretty_assertions = "1"
```

### Edition: `edition = "2024"` คืออะไร

key `edition` เลือก dialect ของภาษาที่ crate ของคุณจะถูก compile ด้วย edition ทำให้ Rust เปลี่ยน syntax และ idiom ได้โดยไม่ทำให้ ecosystem แตกเป็นเสี่ยง — crate ที่อยู่คนละ edition link เข้าด้วยกันได้ปกติ แต่ละ crate จึงอัปเกรดตามจังหวะของตัวเองได้

`cargo new` สร้าง `edition = "2024"` มาตั้งแต่ Rust 1.85 (กุมภาพันธ์ 2025) สิ่งที่ edition 2024 เปลี่ยน เรียงตามลำดับที่คุณน่าจะเจอก่อน:

| สิ่งที่เปลี่ยน | มีผลกับคุณอย่างไร |
|--------|----------------------|
| Let chain | `if let Some(x) = opt && x > 2` compile ผ่าน — เฉพาะ edition 2024 |
| scope ของ temporary ใน `if let` | temporary ถูก drop ก่อนเข้า branch `else` ตัด deadlock ของ lock ไปทั้งกลุ่ม |
| การ capture lifetime ของ `impl Trait` | `impl Trait` ที่ return ออกมา capture ทุก lifetime ที่อยู่ใน scope |
| `unsafe extern` | block `extern` ต้องเขียนเป็น `unsafe extern "C"` |
| สงวนคำว่า `gen` | `gen` กลายเป็น keyword เก็บไว้สำหรับ generator block ในอนาคต |

การย้าย crate เดิมมี 2 ขั้น และ Cargo ทำให้เกือบหมด:

```bash
# 1. rewrite the code so it means the same thing under both editions
cargo fix --edition

# 2. bump edition = "2024" in Cargo.toml, then confirm behaviour
cargo test
```

การ resolve dependency แบบรู้จัก MSRV เป็นกลไกแยกต่างหากของ Cargo ที่ต้อง opt-in เอง — มาจาก field `rust-version` บวกกับ config `resolver.incompatible-rust-versions` (ค่า default คือ `fallback` ตั้งแต่ Cargo 1.84) และ**ไม่เกี่ยวกับ `edition`**เลย เมื่อตั้ง `rust-version` ไว้ พฤติกรรม `fallback` ที่เป็นค่า default จะทำให้ Cargo ข้ามเวอร์ชัน dependency ที่ประกาศ `rust-version` ของตัวเองใหม่กว่าของคุณ แล้วถอยไปใช้เวอร์ชันเก่ากว่าที่เข้ากันได้แทน หากตั้ง `resolver.incompatible-rust-versions = "deny"` จะทำให้กรณีนั้นกลายเป็น error ทันทีแทนที่จะเงียบๆ ลดเวอร์ชันให้

## Unit Testing ด้วย `#[test]`

Rust มีการทดสอบที่สร้างไว้ในภาษาและ Cargo — ไม่ต้องการ framework ทดสอบเพิ่มเติม ใส่ `#[test]` บนฟังก์ชันเพื่อทำเครื่องหมายว่าเป็น test

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b
}

#[test]
fn test_add() {
    assert_eq!(add(2, 3), 5);
    assert_eq!(add(-1, 1), 0);
    assert_ne!(add(2, 3), 6);
}
```

รัน test ทั้งหมดด้วย:

```bash
cargo test
```

### รูปแบบ Module `#[cfg(test)]`

สถานที่ idiomatic สำหรับ unit test คือภายในไฟล์ source ที่ทดสอบ ภายในบล็อก `mod tests` ที่ถูกปิดกั้นด้วย `#[cfg(test)]` Cargo compile module นี้เฉพาะเมื่อรัน `cargo test` ทำให้ไม่อยู่ใน binary ที่ใช้งานจริง

```rust
pub fn multiply(a: i32, b: i32) -> i32 {
    a * b
}

pub fn divide(a: f64, b: f64) -> Option<f64> {
    if b == 0.0 {
        None
    } else {
        Some(a / b)
    }
}

#[cfg(test)]
mod tests {
    use super::*; // bring parent module items into scope

    #[test]
    fn test_multiply() {
        assert_eq!(multiply(3, 4), 12);
        assert_eq!(multiply(0, 100), 0);
        assert_eq!(multiply(-2, 5), -10);
    }

    #[test]
    fn test_divide_by_zero() {
        assert_eq!(divide(10.0, 0.0), None);
    }

    #[test]
    fn test_divide_normal() {
        let result = divide(10.0, 4.0).unwrap();
        assert!((result - 2.5).abs() < f64::EPSILON);
    }
}
```

### Test Assertion

```rust
#[cfg(test)]
mod tests {
    #[test]
    fn demonstrate_assertions() {
        // equality
        assert_eq!(2 + 2, 4);
        assert_ne!(2 + 2, 5);

        // boolean
        assert!(4 > 3);
        assert!(!"hello".is_empty());

        // with custom message
        assert_eq!(1 + 1, 2, "basic arithmetic must hold");

        // panics
        // use #[should_panic] to assert a function panics
    }

    #[test]
    #[should_panic(expected = "divide by zero")]
    fn test_panic() {
        let _ = 1 / std::hint::black_box(0); // this panics — test passes because we expect it
    }
}
```

literal `1 / 0` ตรงๆ นั้นไปไม่ถึงขั้นรันด้วยซ้ำ: การวิเคราะห์ constant-propagation พิสูจน์ได้ว่าการหารนี้ panic แน่นอน จึงปฏิเสธไม่ compile ให้ เพราะ `unconditional_panic` เป็น lint ที่ deny-by-default `std::hint::black_box` ช่วยซ่อนค่า `0` จากการวิเคราะห์นั้น ทำให้ panic เกิดตอน runtime แทน ซึ่งเป็นสิ่งที่ `#[should_panic]` ต้องการเพื่อทดสอบ

```text
error: this operation will panic at runtime
  --> src/main.rs:23:17
   |
23 |         let _ = 1 / 0; // this panics — test passes because we expect it
   |                 ^^^^^ attempt to divide `1_i32` by zero
   |
   = note: `#[deny(unconditional_panic)]` on by default
```

พอแก้แล้ว `cargo test` ก็ compile ผ่านและ test ผ่านจริง:

```text
running 2 tests
test tests::demonstrate_assertions ... ok
test tests::test_panic - should panic ... ok

test result: ok. 2 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s
```

### Integration Tests

ไฟล์ภายใต้ `tests/` คือ integration test ซึ่งทดสอบ public API ของ crate ของคุณในฐานะ consumer ภายนอก

```rust
// @skip-verify multi-file: integration test
// tests/integration_test.rs
use my_lib::multiply;

#[test]
fn integration_multiply() {
    assert_eq!(multiply(6, 7), 42);
}
```

รัน integration test เฉพาะ:

```bash
cargo test --test integration_test
```

รัน test เฉพาะด้วยชื่อ:

```bash
cargo test test_divide
```

รัน test พร้อม output ที่มองเห็น:

```bash
cargo test -- --nocapture
```

### การทดสอบ Async Code ด้วย tokio

สำหรับ async function ใช้ `#[tokio::test]`:

```rust
// @skip-verify crate: tokio
#[cfg(test)]
mod tests {
    use super::*;

    #[tokio::test]
    async fn test_async_fetch() {
        let result = fetch_data(1).await;
        assert!(!result.is_empty());
    }
}
```

เพิ่ม `tokio` ใน `[dev-dependencies]` เพื่อใช้ `#[tokio::test]` โดยไม่ดึง tokio เข้า production binary ถ้าคุณไม่ต้องการที่นั่น

<Callout title="Test รันด้วย cargo test — ไม่ใช่ใน browser runner">
Rust test ใช้ฟังก์ชัน `#[test]` ที่ compile และรันโดย `cargo test` browser Playground รัน `fn main()` เท่านั้น — `cargo test` ไม่พร้อมใช้งานในนั้น เขียนโค้ด test ของคุณใน Cargo project ในเครื่องและรัน `cargo test` จาก terminal ใช้ `cargo test -- --nocapture` เพื่อดู output จาก `println!` ใน test ที่ผ่าน
</Callout>
